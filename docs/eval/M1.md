# Note quality evaluation (M1 items 2, 3 and 5)

`openbark eval` drafts a note for each synthetic consult and checks it against the facts each script declares under `expected:` in `packages/eval/fixtures/scripts/*.yaml`:
- vitals (with values);
- medications (with dose or duration);
- phrases that must appear;
- phrases that must not appear;
- invented numbers, from the faithfulness pass (a hard fail);
- citation errors.

Transcripts are cached in `target/eval-cache`, so prompt changes re-run only the note step.

Model: Gemma 4 E4B (QAT Q4_0), RTX 4080. The GPU was shared with other software during these runs, so note times are inflated and only the fact scores should be compared.

| Change | Facts found | Invented numbers |
|---|---|---|
| Baseline (whitespace limited to one space, prompt from M0) | 33 / 44 (75%) | 0 |
| llama.cpp's default whitespace rule restored, plus rules on units and patient details | 37 / 44 (84%) | 0 |
| Vocabulary hints added to the transcript (prompt grew) | 28 / 44 (64%): numeric vitals corrupted again | 0 |
| **Measurements written as numbers with a separate `unit`**, plus JSON format examples in the prompt | **36 / 44 (82%)**: every vital correct, with units | 0 |
| **Second recogniser** (Whisper turbo) on segments with numbers or clinical terms; rules for medications and declined tests | **39 / 44 (89%)**: smoke 5/5, as Whisper heard "otitis" | 0 |

## Findings

1. **Limiting JSON whitespace to one space breaks Gemma 4 E4B.**
   - It saves about 40% of output tokens, but fields whose value starts with a digit came out as junk such as `"} , "`.
   - Restoring llama.cpp's whitespace rule fixed most cases.
   - Full grammar masking (instead of the lazy check) made no difference to quality and was about 6× slower.
2. **E4B wants to write measurements as bare JSON numbers.**
   - Forcing every value to be a string made numeric fields fragile: any prompt change could tip them back into junk.
   - The schema now accepts a number or a string, with a separate `unit` (`{"value": 4.1, "unit": "kg"}`).
   - Since then, every numeric vital has come out right, with its unit.
3. **Hotword biasing doesn't help Parakeet.** With hotwords on, sherpa-onnx dropped the drug name and wrote "1 5 inch". Vocabulary is handled by **visible hints** instead:
   - `packages/vocab/veterinary.tsv`, extendable in `<data>/OpenBark/vocab.tsv`;
   - a phonetic plus spelling match;
   - the transcript text is never changed.

   On the fixtures this produced 8 hints, all correct: marapitin → maropitant, fronovetmab → frunevetmab, amlidipine → amlodipine, panlucopenia → panleukopenia, and others. The note now says "Maropitant".
4. **Condition names don't get loose hints.** "artitis" (said: *otitis*) scores 0.948 against *arthritis* and 0.783 against *otitis*, so conditions need a near-exact match. A missing hint beats a misleading one.

## Remaining misses (82% run)

- **feline:**
  - LRS fluids weren't listed under medications; they appear under procedures instead.
  - "client declined x-rays" was left out.
  - Hydration "about six percent" is correct, but the scorer expects digits.
  - "MurdaZipine" was hinted correctly but not used by the model.
- **multipet:** FVRCP (said as letters), and the blood pressure figure "175".
- **smoke:** "otitis" (misheard as "artitis"; no hint, by design).

## Second-opinion recognition (M1 item 4)

Segments with numbers, hints or drug- and condition-like words are recognised again by Whisper large-v3-turbo (int8, CPU). During live recording this runs in the background. On the paced 9.6-minute consult it checked 19 of 57 segments and found **both** of the primary recogniser's number errors:
- "10 milliliters of lactated ringers" was heard as **100** by the second recogniser;
- "$120" was heard as **$320**.

Notes that rely on a disputed number are flagged, and each disputed transcript line shows what the second listen heard. Terms the second recogniser heard (for example *otitis*) become hints. Neither model's text replaces the other.

## Patient details

Patient name, last name and reason for visit are entered by the clinic, time-stamped (`entered_at`, plus `updated_at` on later changes) and stored in `session.json`. The note model receives them as context marked "not evidence".

Even when told only to fill patient details that were said, E4B still wrote "Species: dog" for a patient never described as one. Patient-detail fields are therefore checked word by word against their cited line, with species synonyms allowed. Unsupported values are flagged in the draft ("Not said in the cited line").
