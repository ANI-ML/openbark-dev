# M1: Desktop MVP (vet-usable)

Status: **in progress**, started 2026-10-17. The product owner said "keep proceeding with all features".
Builds on M0 (`docs/plans/M0.md`). Items are listed in delivery order: each must be demonstrable before the next starts.

## Goal

A vet can record a consult on a laptop, see the transcript live, and get a faithful draft within about 30 s of pressing stop. They can then review and edit it, mark it reviewed, copy it section by section, and find it again later, all offline.

## Work items

| # | Item | Why now | Acceptance |
|---|---|---|---|
| 1 | **Live recording** (desktop: microphone → `audio.wav` in the session, with live VAD and speech-to-text; browser: record, then upload) | The core scribe action. Until now the app only took files. | 10-minute live recording from the default mic, with no dropped audio (frame count matches the clock). Transcript visible while recording. Note ready ≤ 30 s after stop on the reference box. Machine kept awake throughout. |
| 2 | **Eval harness v0** (`openbark eval`: scores notes against each fixture's `expected` facts) | Measure quality before changing prompts. | One command runs all fixtures and prints facts found/missed, invented numbers, and citation errors. |
| 3 | **Note quality pass**: units, patient details only if stated, chief complaint, citation accuracy | M0 found an invented "Species: dog", dropped units and wrong citations. | Eval improves on every fixture. Zero invented numbers. Patient fields stated or null. |
| 4 | **Safety: number cross-check.** Segments containing numbers are re-recognised with Whisper turbo; disagreements are flagged with click-to-audio. | ASR turned "100 mL" into "10 mL" (M0 perf report). | The paced fixture's dose error gets flagged. No flags on the clean fixtures. |
| 5 | **Veterinary vocabulary**: hotword biasing plus a post-correction dictionary (drugs, breeds, terms); user-extensible | "maropitant", "mirtazapine" and "otitis" were misheard. | Those terms come out correct on the fixtures. A user can add words. |
| 6 | **Review and sign**: edit sections, accept or reject, mark reviewed by a DVM (signed notes immutable; addenda), per-section copy | Brief §3: a note stays a draft until a DVM signs. Product owner asked for one-click copy. | Edits are saved as a new revision. Signing locks the note. Copy works per section and for the whole note. |
| 7 | **Consent prompt** before recording, per jurisdiction (one-party/two-party), recorded in `session.json` | Brief §2.2 parity checklist. | Recording can't start without the consent step, and consent is saved with the session. |
| 8 | **Model manager GUI**: catalog, download with progress, hardware-fit badge | Today models need the CLI. | First run, with no models: download the defaults from the UI and reach a working note. |
| 9 | **More templates**: discharge instructions, client summary (plain language), callback note | Brief M1 scope. | Each template is schema-valid, passes the faithfulness check, and is covered by the eval. |
| 10 | **Encrypted at rest**: SQLCipher index of sessions/notes/revisions; audio encrypted per session; key in the OS keychain | Brief §3. Known M0 gap (decision 8). | No plain-text clinical data on disk outside exports. Sync-ready IDs (ADR-0005). |
| 11 | **Local user picker / PIN** with roles (DVM, RVT, reception) | Product owner asked for login. Full roles and audit arrive with the Hub (M4). | Who recorded, edited and signed is stored on each revision. |
| 12 | **PDF export** (clinic letterhead) and per-PIMS clipboard presets | Brief M1. | PDF of a signed note. Plain text, RTF and Markdown copy. |

## Carried over from M0 (in parallel)

## Risks

- Live capture on Windows/macOS through `cpal`: device permission prompts (macOS microphone entitlement), sample-rate negotiation.
- Prompt changes can trade one fact for another. That's why the eval harness (item 2) comes first.
- Encryption work touches every storage path. It's done once, after the session format settles (item 10).
