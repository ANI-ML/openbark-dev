# M0: Spikes and skeleton

Status: **approved 2026-10-17** (product owner). Target: 2 weeks from approval.
Name: **OpenBark**. Repo: `ANI-ML/openbark` (private until launch). See "Decisions (resolved)" at the end.

## Goal

At the end of M0 a developer can:
1. clone the repo and build it on Windows or macOS;
2. turn a recorded consult into a SOAP draft with one command, fully offline;
3. open a desktop shell that shows the same result.

The two riskiest platform assumptions (S1 and S2) have been tested and recorded as ADRs.

What a vet can do at the end of M0: nothing yet without a developer's help. M0 is infrastructure. The first vet-usable build is M1.

## In scope

1. **Monorepo skeleton.** pnpm 11 workspace, Turborepo, and a Rust workspace under `engine/`. The layout follows master prompt §4.1. Empty packages get a README and a placeholder test so CI exercises them. `apps/mobile`, `apps/web`, `apps/hub` and `apps/browser-extension` are created as stubs only.
2. **Engine (configuration A from S2).**
   - Crates: `os-engine`, `os-llm` (llama-cpp-2), `os-asr` (sherpa-onnx STT + Silero VAD), `os-diar` (sherpa-onnx diarization), `os-models` (catalog + resumable downloader + SHA-256 check) and a stub `os-store` (SQLCipher open/migrate only).
   - Backend traits report their capabilities.
3. **CLI** `openscribe`:
   - `models list`
   - `models pull <id>`
   - `transcribe <wav|m4a|mp3> [--diarize]` (outputs JSONL)
   - `note --template soap` (reads JSONL on stdin; outputs SOAP JSON + Markdown)
   - `bench` (time to first token, tokens/s, real-time factor, peak memory)
   - `probe` (hardware report: RAM, VRAM, GPU API, CPU features)
4. **SOAP template v0.** YAML plus a JSON Schema in `packages/templates/soap/`. Sections are marked `required | optional | if_discussed`, and the rule "absent means *Not discussed*" lives in the schema and the prompt. Golden tests cover rendering.
5. **Desktop shell.** Tauri 2.12 app on Windows and macOS. One screen: pick a file, watch the transcript stream in, generate the SOAP note, view the result, copy it. The design-token stub goes in `packages/ui` with light and dark themes. **M0 doesn't do the polished UI**; that's M1.
6. **Spikes.**
   - [S1](../spikes/S1-mobile-audio-and-inference.md): mobile audio and on-device inference.
   - [S2](../spikes/S2-native-linking.md): native linking. Its configuration A *is* item 2.
   - **S3 web probe** (1 day): Gemma 4 E2B on WebGPU, comparing Transformers.js 4.3.1 (q4f16 ONNX) with `@litert-lm/core` 0.18.1, plus Whisper or Moonshine in the browser. It records load time, tokens/s and browser support. The outcome goes in an ADR, and the full PWA stays in M5.
7. **Synthetic test consults.** Three scripts written for us: a canine wellness visit (5 minutes), a feline vomiting sick visit (10 minutes, with vitals and drug doses), and a multi-pet visit (20 minutes, three speakers). Each has a gold SOAP note.
   - They're rendered to WAV **locally** with a sherpa-onnx TTS voice. The voice model's license must be confirmed before it's committed.
   - They're stored in `packages/eval/fixtures/`.
   - This is the seed of the eval harness (master prompt §4.8). Real consented recordings come later.
8. **CI** (GitHub Actions):
   - lint and test the TS packages;
   - `cargo test` and `clippy`;
   - build the engine and desktop app on Windows x64, macOS arm64 and Linux x64; build-only for Android, iOS and macOS x86_64;
   - the single-ggml symbol test;
   - an **offline e2e test** on Linux that runs the CLI with no network after the model cache is restored;
   - the network allow-list test (step 1: the CLI's only HTTP client is `os-models`, which is checked against `docs/network.md`).
9. **Docs.**
   - ADR-0000 (template), ADR-0001 (inference libraries), ADR-0002 (mobile framework), ADR-0003 (web inference) and ADR-0004 (monorepo/tooling).
   - `docs/network.md`, `NOTICE` (with Parakeet's CC-BY attribution), `CHANGELOG.md`, `docs/demo/M0.md` (the demo script) and `CONTRIBUTING.md`.
   - Root `CLAUDE.md`, pointing at the master prompt plus the rules.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| No Mac for iOS, the macOS app or Metal performance checks | **High** (this box is Windows) | GitHub macOS runners cover builds. The iOS device test and Apple Silicon latency checks need hardware: see decision 2. |
| llama-cpp-2 can't load GGUF files over 4 GB on MSVC (#951) | Medium | Tested on day 1. Fallbacks: `dynamic-link` to the official llama.cpp v0.6.0 DLL, or patch upstream. |
| sherpa-onnx's prebuilt download breaks reproducible builds | Medium | Cache it with checksums and use `SHERPA_ONNX_LIB_DIR`, as in S2 step 6. |
| Tauri mobile background audio fails | Medium | S1 decision rule. Inference can still offload to the Clinic Hub. |
| Very fresh dependencies (React 19.3.1, Vitest 5, turbo 2.11.9 are days old) | Medium | Exact pins plus pnpm's 24-hour release-age rule. Roll back a version if CI shows regressions. |
| Gemma 4 audio input isn't supported in llama.cpp | Medium | Only blocks the experimental audio-native path (S2 configuration C). The default pipeline doesn't depend on it. |
| The name is unavailable | **High** | Decide before public repo creation. See decision 1. |

### Original decision notes (kept for the record)

1. **Name (needed before a public repo exists).**
   - **"OpenScribe" is taken in our exact field.** `sammargolis/OpenScribe` is an MIT human-medicine AI scribe with 220 stars, running openscribe.org. The prompt's `Pl4tt/OpenScribe` is just a fork of it. Two other "OpenScribe" dictation apps also exist.
   - **"OpenVetScribe" has no direct hits, but it's still risky.** OpenVet, Inc. filed a USPTO application for **OPENVET** (serial 99866007) for veterinary SaaS in class 42, filed 2026-06-04 and pending. There's also a commercial **VetScribe** product.
   - CIPO in Canada showed no OPENSCRIBE or OPENVET marks.
   - **My recommendation: pick a new, distinctive name** without "Open" + "Vet", and run a proper search on it. I'll use "OpenScribe" as a placeholder in code until then and keep it to one constant, so renaming is cheap.
2. **Apple hardware.** Is there an Apple Silicon Mac (and an iPhone) I can reach for the iOS half of S1 and the M-series latency check? If not, S1 runs Android-only in M0 and iOS moves to early M1.
3. **GitHub.** Which org/repo should the project live in, and should it be private until launch? The GitHub connector here isn't authorised, so I'd create the repo with `gh` or you'd create it.
4. **The five changes from the master prompt** listed above. Do you accept them, especially #1 (sherpa-onnx in place of whisper.cpp)?
5. **Default desktop model** (master prompt §9.3). I propose the M0 benchmark decides it: 12B if it meets ≤60 s on the 4080 *and* on M-series hardware with 16 GB, otherwise E4B. 12B also accepts audio, while 26B and 31B don't.

Decisions 4–6 from master prompt §9 (consent defaults, gallery governance, catalog hosting) aren't needed until M1–M2.
