# M0 performance (acceptance test M0-3)

**Target (master prompt §3):** the first draft of a 10-minute consult appears in **≤ 60 s** on an M-series Mac or a 12 GB-VRAM GPU with the default model set.

## Windows reference box, 2026-10-17

The reference box is an RTX 4080 (16 GB VRAM), an i7-12700KF and 64 GB of RAM, running CUDA 12.9 with a build targeting this GPU's architecture only (sm_89).

> **The GPU was shared during these runs.** Final Fantasy XIV (`ffxiv_dx11.exe`) was running, using about 35–40% of the GPU and 4 GB of VRAM, along with Parsec streaming. Back-to-back runs varied by up to 2×. **Treat every number here as an upper bound.** A clean rerun on an idle GPU is still pending.

**Input:** `feline-vomiting-paced`, a 9.6-minute synthetic consult with 2 speakers and about 1,400 spoken words, rendered with slower speech and exam-length pauses. Measured with `openbark bench --diarize` and saved to `results/rtx4080-win11-20261017/`.

| Stage | E4B (QAT Q4_0) | 12B (QAT Q4_0) |
|---|---|---|
| VAD | 2.8 s | 2.6 s |
| Diarization (CPU) | 40.9 s ‡ | 39.3 s ‡ |
| Speech-to-text, Parakeet TDT v3 int8 (CPU) | 43.5 s ‡ | 41.3 s ‡ |
| LLM load | 3.0 s | 5.3 s |
| Prompt (2,590 tokens) | 0.64 s | 1.45 s |
| Generation | 1,435 tok at 58 tok/s = 25.4 s | 1,384 tok at 22 tok/s = 63.9 s |
| **Total, batch from file** | **76.8 s** | **115.1 s** |
| Peak RAM | 3.4 GB | 7.2 GB |
| Faithfulness: numbers absent from the transcript | 0 | 0 |
| Faithfulness: correct value cited to the wrong segment | 5 | 5 |

‡ Diarization and speech-to-text run **in parallel**, so their times overlap: together they took about 45 s of wall time. On the same audio without the contention, sequential runs measured ASR at 21.8 s and diarization at 21.5 s.

### What the numbers mean

- **Batch from a file (what M0 measures):** E4B misses 60 s on this shared machine, at 77 s.
- **Live recording (the real use, from M1):** transcription and diarization happen *during* the consult, so the wait after pressing stop is roughly LLM load plus generation. That's about **29 s for E4B** and 71 s for 12B, even under contention. M1 will measure this directly, once live capture exists.
- **12B** misses the target under contention. It needs a clean rerun before choosing the default desktop model (decision 5).

### Fixes made during the spike (each measured)

| Change | Before | After |
|---|---|---|
| Grammar checked lazily (one token, then the full mask only on rejection) and whitespace restricted | 20.7 tok/s, 2,337 output tokens, E4B | 45–58 tok/s, 1,435 tokens |
| Diarization clustering threshold 0.5 → 0.7 | 6 speakers found (truth: 2) | 2 found; purity 99.7% (feline) and 99.6% (multipet, 3 speakers) |
| Diarization window step 0.1 → 0.25 | 37.5 s / 46.7 s | 14.9 s / 18.5 s, with identical purity |
| ASR and diarization run in parallel | sequential sum | the longer of the two |

### Safety findings (not speed, but found here)

1. **Speech-to-text dropped "hundred" twice** on the slower, paced audio: "one hundred milliliters" became "10 milliliters", and "three hundred and twenty dollars" became "$120". At normal speed it was correct. The faithfulness check can't catch this, because the transcript itself is wrong. **Proposal (M1):** re-recognise every segment that contains a number with a second model (Whisper turbo through sherpa-onnx), and flag any disagreement for review with click-to-audio.
2. **Drug and patient names are misheard:** "maropitant" became "Maritrant"/"marapitin", "mirtazapine" became "Murdazappine", "Mochi" became "Ma Chai", and "otitis" became "artitis". The veterinary vocabulary pass in master prompt §4.4 (hotwords plus a post-correction dictionary) should move up to M1.
3. **The model cites the wrong segments for correct values** (5 per note). That's now reported as its own category and flagged in the draft. Prompt tuning and a citation-repair pass are M2 work.

## Live recording (M1 item 1), 2026-10-17

The same 9.6-minute consult was played through the live path **in real time**, as if from a microphone (`openbark record --file … --realtime`):

| | Result |
|---|---|
| Transcript complete after stop | **0.0 s**: every utterance was already recognised during the consult |
| Speaker labels (live tracker, threshold 0.65) | 2 of 2 speakers; purity 98–100% across all four fixtures |
| Note saved after stop (E4B) | **13.1 s**, against the ≤ 30 s M1 target |

This is the real-use latency. The 76.8 s batch figure above only applies when a finished file is processed from scratch.
